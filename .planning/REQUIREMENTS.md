# Requirements: GSD Run Dashboard

**Defined:** 2026-07-24
**Core Value:** You can check any registered GSD project's phase progress, current status, and live subagent activity from the browser, instead of running GSD status commands in a terminal.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases. This is a retroactive ingest: REG, RM, ACT, GIT, CONV, and UI requirements are already implemented and shipped on `main`. Phase 7 packaging and Phase 07.1 integration closure are verified separately.

### Project Registry (REG)

- [x] **REG-01**: User can add a project folder to the dashboard via folder picker
- [x] **REG-02**: User can remove a project from the registry without touching its files
- [x] **REG-03**: Dashboard validates that an added path is an existing directory; GSD metadata is detected when present but is not required for registration
- [x] **REG-04**: User can discover GSD projects via scan-folder discovery feature
- [x] **REG-05**: Registry persists across restarts in `~/.claude/gsd-web/projects.json`

### Roadmap & Progress Parsing (RM)

- [x] **RM-01**: Dashboard parses `ROADMAP.md` phases/plans/success criteria into structured data
- [x] **RM-02**: Dashboard parses `STATE.md` YAML frontmatter and Current Position section
- [x] **RM-03**: Dashboard also supports `.gsd/gsd.db` SQLite-based projects (`gsdDbReader`)
- [x] **RM-04**: Progress bar uses `STATE.md` percent when present, else computed from ROADMAP checkboxes
- [x] **RM-05**: Missing/malformed files degrade gracefully without hard errors
- [x] **RM-06**: User can manually refresh roadmap/progress view

### Live Agent Activity (ACT)

- [x] **ACT-01**: Claude Code hook records PreToolUse/PostToolUse/Stop events for Task-type subagents
- [x] **ACT-02**: Dashboard shows currently running subagents with type, description, elapsed time via SSE
- [x] **ACT-03**: Stale status entries (>2 hours) are ignored/hidden
- [x] **ACT-04**: Hook never throws/blocks the user's Claude Code session
- [x] **ACT-05**: Roadmap view auto-refreshes when a subagent activity completes

### Git Milestone Detection (GIT)

- [x] **GIT-01**: Dashboard shows the newest git tag that's an ancestor of the current branch's remote-tracking ref
- [x] **GIT-02**: Dashboard shows graceful states for no-repo/no-remote/no-tags scenarios
- [x] **GIT-03**: No git network operations are performed (local refs only)

### Convert to GSD Flow (CONV)

- [x] **CONV-01**: User can configure CLI tool, terminal app, and command templates in Settings
- [x] **CONV-02**: User can prepare, review and explicitly apply a GSD adoption proposal for a registered non-GSD folder
- [x] **CONV-03**: GSD adoption preserves source code and existing planning, supports guarded rollback, and refreshes project status after completion

### Dashboard Interface (UI)

- [x] **UI-01**: User can view, filter and manage all registered projects in the portfolio table
- [x] **UI-02**: User can view a project detail page with roadmap tree, running-now panel, and git panel
- [x] **UI-03**: User can view/edit Settings (CLI tool, terminal app, command templates)
- [x] **UI-04**: Each panel degrades independently on error (no whole-page crash)

### Single-Binary Packaging (PKG)

- [x] **PKG-01**: A unified CLI entrypoint (`server/cli.js`) supports `serve`/`hook`/`install-hook` subcommands
- [x] **PKG-02**: `npm run build:binary` compiles the dashboard into single-file executables for `darwin-arm64`, `darwin-x64`, `linux-x64`, `linux-arm64`, `windows-x64` via `bun build --compile`
- [x] **PKG-03**: Compiled binary serves frontend from an embedded asset manifest (generated by `scripts/generate-assets-manifest.js`) instead of `express.static`
- [x] **PKG-04**: Compiled binary's `hook` subcommand reuses `hooks/gsd-web-hook.js`'s `handle()` logic via exported `runHookFromStdin()`
- [x] **PKG-05**: Compiled binary's `install-hook` subcommand reuses `installHooks(hookCommand, settingsPath)` to register the hook pointing at the binary path instead of the `node` script
- [x] **PKG-06**: Missing `server/generatedAssets.mjs` at `serve`-time produces an explicit error message, not a confusing crash
- [x] **PKG-07**: Existing `npm run dev` / `npm start` / `npm test` workflows remain unaffected by packaging changes

## v2 Requirements

None currently deferred. Cross-platform "Convert to GSD project" and CI/release automation for multi-platform binaries are treated as permanent Out of Scope (see PROJECT.md), not deferred v2 work.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Multi-tenant / hosted / authenticated deployment | Single-user, localhost-only tool by design |
| Correlating running subagents to specific GSD phase/plan numbers | Hook only knows the subagent's own task description; cross-referencing would be fragile |
| Git network operations (fetch/push) from the dashboard | Local-refs-only constraint keeps the tool read-only and side-effect-free |
| Cross-platform (Linux/Windows) "Convert to GSD project" terminal launch | Depends on `osascript` GUI/window-server access; explicitly macOS-only |
| Docker packaging | Rejected — `osascript` GUI access unavailable in containers; superseded by Bun single-binary packaging |
| CI/release automation for multi-platform binary builds | `npm run build:binary` is manual/local-only per SPEC |
