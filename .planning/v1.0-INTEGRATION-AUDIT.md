## Detailed findings

### B1 — BLOCKER: no folder-picker connection (REG-01)

`web/src/components/AddProjectDialog.jsx:19–25` renders a controlled plain text input. Its path flows correctly through POST/registry/list, but there is no `showDirectoryPicker`, directory file input, native picker endpoint, or other picker selection handler in the frontend. User can type a path or scan a typed parent folder, but cannot complete the expressly promised picker flow. This is a missing UI→registration connection, not a backend registration failure. No approved pivot evidence specifically waives the picker requirement.

### B2 — BLOCKER: success criteria never reach the roadmap response (RM-01)

`server/lib/roadmapParser.js:1–75` recognizes phase checklist/header, goal, dependencies, requirements and plan rows only. No success-criteria field is created; `RoadmapTree.jsx` renders goal/plans only. A pure Node probe with `**Success Criteria**:` and `1. User sees criterion` produced a phase containing no criterion text. Thus the required source→structured-data link is absent even though phases/plans work. Current parser tests assert phases/plans, not this part of RM-01.

### B3 — BLOCKER: completed activity does not refresh roadmap (ACT-05)

`web/src/components/RunningNowPanel.jsx:14–17` subscribes with `setRunning` only. `web/src/pages/ProjectDetail.jsx:21–39` fetches roadmap on id change; lines 64–70 refetch only after migration, while line 75 supplies no activity completion callback. The new AnalysisPanel completion at line 59 refreshes only ExecutiveBriefPanel's key. SSE deletion correctly clears the running list, but does not reload roadmap/progress in the detail view. Dashboard's 30-second polling is neither this detail consumer nor a completion-triggered refresh.

### W1 — WARNING: settings read error is stored but hidden (UI-03, UI-04, CONV-01)

`SettingsPage.jsx:9–20` catches GET failure into `error`, then returns Loading whenever settings is null. The alert is below that early return. A failed request therefore leaves an indefinite loading state with no failure feedback/retry. Successful GET/edit/PUT is wired; save errors are visible after settings loads. No browser fault test covers this path in the saved backend suite.

### W2 — WARNING: stale age and elapsed time update only on filesystem events (ACT-02, ACT-03)

`activityStore.js:23–24` correctly recalculates/filter ages whenever called; `sse.js:13–38` sends on subscription and file events only. RunningNowPanel has no timer. An orphan shown before it crosses two hours stays on an already-open detail page until another status event or reconnect; displayed elapsed time also freezes between events. Initial stale records are hidden and dashboard list polling reevaluates them. Watch failures are silently reduced to an initial snapshot; EventSource errors have no UI feedback.

### W3 — WARNING: scan-add rejection has no feedback boundary (REG-01, REG-04, UI-04)

`ScanFolderPanel.jsx:20–24` awaits add without catch, whereas handleScan catches errors. A disappeared folder or a concurrent duplicate registration rejects the click handler without a visible alert or refreshed results. Direct AddProjectDialog does catch the same API error. Successful scan→add→refresh is connected.

### W4 — WARNING: detail has no manual refresh action (RM-06)

The portfolio's Refresh discovery control recomputes displayed progress and meets a manual portfolio refresh path. ProjectDetail offers no refresh button for the roadmap/tree; current refetch triggers are id change and migration. A user reading a changing roadmap must reload/navigate or return to the portfolio. This qualifies RM-06 without inventing a wholly absent manual refresh capability.

### W5 — WARNING: installed executable paths are not shell-quoted (PKG-05, PKG-04, ACT-01)

`server/cli.js` builds `process.execPath + " hook"`; `scripts/install-hook.js` stores that command verbatim. The source-script installer similarly interpolates an unquoted script path. Installation/backup/idempotency is verified, but placing the executable or checkout in a path with spaces can cause the shell hook invocation to fail before shared hook logic runs. This is also retained in Phase 7's existing review warnings. Native evidence uses a path without spaces.

## Approved scope drift (not counted as integration blockers)

- **D1 / REG-03:** registration deliberately accepts all directories. `registry.addProject` validates existence/directory/canonical duplicates, not GSD presence; `isGsdProject` still labels scan results and both GSD formats. Original reject-non-GSD wording is superseded by the user-approved portfolio direction. The 2026-11-01 portfolio spec explicitly says tracking never requires migration. Requirements need reconciliation, not restoration of the old restriction.
- **D2 / UI-01:** `PortfolioTable` replaces the original card grid. Dashboard data and detail links remain wired; `ProjectCard` is dormant. Table presentation is approved scope drift.
- **D3 / CONV-02, CONV-03:** terminal conversion is no longer reachable from scan UI; `convertProject` and `handleConvert` are dormant even though the route/settings/osascript code remains. Deliberate Prepare/Review/Apply GSD adoption replaces conversion and immediately refetches roadmap/git via `onChanged`. Already registered non-GSD folders do not need to become addable after conversion. Treat old conversion wording as superseded, not as an unreported passing terminal flow or a newly discovered unauthorized regression. Real osascript launch was not executed by this audit. The newer migration writer is outside the original read-only milestone and requires reconciliation with that original constraint.
